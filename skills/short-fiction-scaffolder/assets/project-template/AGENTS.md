# Repository Guidelines

## 项目结构与版本

本仓库用于维护一部中文商业短篇小说。`README.md` 只标记当前推荐稿；`docs/outline.md` 是唯一、持续维护的大纲。正文按 `docs/drafts/vN.md` 编号保存，修改说明位于 `docs/revision-notes/vN.md` 并与正文版本一致。发布资料统一维护在 `docs/publication/metadata.md`，发布素材放在 `assets/`，主封面固定为 `assets/cover.png`。

重大改写必须创建下一个正文版本，不得覆盖历史稿。初始 `v1.md` 通常不需要修改说明；从 `v2.md` 起，为每个新版本创建同号修改说明。不要增加 `latest.md`、`current.md` 或其他重复表达当前版本的文件。推荐版本变化时更新 README 链接。

## 创作与修订流程

修改故事前，先阅读 `docs/outline.md`、README 指向的当前正文，以及同号修改说明（若存在）。需要大改时，先给出诊断和可执行的修订方案，确认后再创建下一版本。除非任务明确要求，不要修改旧版本正文。

大纲只维护稳定的作品定位、人物关系、时间线、世界规则、结构、伏笔和结局约束。不要为每一稿复制一份大纲。

## Markdown 与文字规范

所有文档使用 UTF-8 Markdown，每份文档只使用一个 H1。正文采用自然的中文标点，`---` 只用于场景或章节分隔。段落应适合移动端阅读，但要变化句长和段落长度，避免机械短句堆叠、重复总结、角色声音趋同或刻意制造金句。

## 内容校验

修订后同时检查改动场景的前后衔接，并核对：

- 人物姓名、年龄、身份和关系
- 时间线、空间移动和事件顺序
- 世界规则、能力边界和因果关系
- 伏笔的埋设、推进和回收
- 相邻场景的动作、道具和情绪连续性
- 正文与 `docs/outline.md` 的一致性
- 篇幅是否符合既定目标

确认旧稿仍然存在且未被意外修改。发布前同步检查正式稿路径、无剧透简介、标签、内容提示、署名和封面信息。

## 本地检查与权限

可使用以下只读检查：

- `find docs -type f -name '*.md' | sort`
- `wc -m docs/drafts/vN.md`
- `rg -n '^# ' README.md AGENTS.md docs`

如果项目已经使用 Git，再运行 `git status --short` 和 `git diff --check`。初始化项目不代表获准提交、推送、创建远程仓库或发布；这些操作必须由用户明确要求。
